# Studio Layers
图片 → 候选图层 → 逐项核对 → Figma 原生图层。原有 DESIGN.md 分析、套版和品牌配置已从网站移除。旧项目存储未清除，旧核心库和回归测试暂保留，不进入新工作流。

## 运行
使用仓库既有 Node.js 与 pnpm 环境：
```
pnpm install --frozen-lockfile
node server.mjs
```
打开 http://127.0.0.1:4174 ，不要直接打开 index.html。STUDIO_PORT 或 PORT 可更改端口；STUDIO_HOST=0.0.0.0 用于现有 Docker / Render 部署。没有新增生产依赖。

## 工作方式
- 最多20张 PNG / JPEG / WebP，每张≤30MB，最大边16384px、总像素≤3200万。
- 模型提出文字、矩形、椭圆候选；不增删改原文，不凭空重建照片。
- 上传图片默认不发往模型。先选择服务器配置或页面内存中的个人接口，确认服务地址、模型、图片数量后才发送总览和必要切片。支持 Responses、Chat Completions、JSON 和完整 SSE 响应。超时或HTTP错误不自动重试。
- 每个候选都经过原图像素检查。只有连续纯色背景、前景/背景颜色吻合且形状几何可靠的候选允许启用。启用项会从位图底图清除，再成为独立原生图层，避免双份原文字。此检查不能证明语义识别正确，用户必须核对原文和区域。
- 不确定、照片、透明、渐变、纹理、描边等区域保留位图。不承诺任意图片完整矢量化、恢复被遮挡背景或准确识别字体。
- 支持手动画出文字区域、输入和修改原文、字体、字号、颜色、坐标及范围；重新检查后再启用。
- 原图/重建切换；超出区域的文字阻止确认。逐图勾选确认后才可导出。
- 保存与备份采用独立 IndexedDB 数据库 studio-layers-v1，不接触旧项目库；不存个人密钥。恢复后重新核对。
- ZIP 包含 figma-import.json、离线插件、原尺寸PNG预览、原图PNG、图层报告和说明。仅保留位图时明确显示0个可编辑图层。
- 超过4096px的底图按像素切片，所有图片资源≤4096px；画板和文字仍为原尺寸，不缩小长图。

## 模型配置
可在页面设置个人接口；密钥仅存在当前页面内存，刷新后清除。个人请求不会修改服务端配置，也不会影响其他用户。可选服务器环境变量：
```
STUDIO_VISION_BASE_URL=https://api.openai.com/v1
STUDIO_VISION_MODEL=服务商提供的支持图片输入的准确模型ID
STUDIO_VISION_PROTOCOL=responses
STUDIO_VISION_KEY=服务器密钥
```
协议也可填 chat。服务器只返回已配置状态、地址、模型和协议，不返回密钥。旧 /api/config、/api/vision、/api/ocr 返回410，不允许网页请求修改共享配置。原有 Render 配置名称保持兼容。公开服务使用共享服务器密钥时，请通过部署平台控制访问和额度。

## Figma
见 [插件说明](figma-plugin/README.md)。导出不是 .fig 源文件，需要 Figma 桌面端开发插件导入。插件离线创建新画板，不覆盖已有节点，失败移除本次新建节点。文字保留完整字符串，字体缺失或排版高度改变会提示。必须在真实 Figma 中再次检查字体、换行、基线与清底效果。
